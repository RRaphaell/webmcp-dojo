## 3. New organizer guidance since Aug 31

### Update, Sep 2 (~11:30 AM PT) — "The deadline is tomorrow ⏰" (webmcp.devpost.com/updates/46162)
- **New hard constraint we did not have: judging runs until September 21 at 5:00 PM PT, and the project must stay live, public and unchanged for that entire window.** Verbatim: *"Judging runs until September 21st at 5:00 PM PT. Your project needs to stay live, public, and working exactly as you presented it for that entire period. If you keep building on the same repo or the same live site after the deadline, **you put your eligibility at risk**."* Rules quoted: *"Once the Submission Period has ended, you may not make any changes or alterations to your Submission"* and the project *"must function as depicted in the video and/or expressed in the text description."*
- Full submission checklist, including three items worth acting on: **"Testing instructions are filled in, with credentials if your app requires a login"**; **"Repo contains your actual WebMCP tool registration code, plus everything needed to run the project"**; license *"visible in the About section"* checked **in an incognito window**.
- Operational: *"Open your live URL somewhere clean. Use a new incognito window in a WebMCP-capable browser, with no cached login. Then run the task an agent is supposed to be able to do. This is the single most common way a working project looks broken to a judge."*
- *"Aim to have your submission in about 3 hours before the deadline"* (i.e. ~10:00 AM PT).

### Update, Sep 1 — "2 days left, and what judges actually look for 🔍" (updates/46161)
- **Video, tightened vs what we had:** *"Show the project working in the first 10 to 15 seconds. Skip intros and title screens."* (CONTEXT.md says 20s — tighten.) Also: *"Start already logged in"*, *"Do not type live. Paste in long text, or cut to the finished result"*, *"Show one strong example. You do not need to repeat the same feature"*, *"Save your team story and your inspiration for the written description, not the video."*
- **Description:** must answer the same four questions we have. Their example of good vs bad is quotable: *"'An agent can complete a multi-step booking in one turn, instead of clicking through six screens' tells us something. 'Leverages WebMCP for seamless agentic experiences' tells us nothing."*
- **New, and it touches our name:** *"Do not use AI to: name your project (AI-generated names all sound alike and blur together across hundreds of submissions, so **pick something specific that says what it does**); describe your project in vague, generic terms; or overstate what is actually running. Show the real thing working."* AI-assisted building is explicitly welcome.
- Judging criteria restated verbatim, unchanged from CONTEXT.md §3.
- **Prize correction:** each of the ten winners takes **$3,500 cash** ($3,000 OpenAI + $500 Netlify), plus $10,000 Cloudflare credits, $4,200/yr Vercel credits, $300 Render, $250 Shopify gear, 3-month Google AI Ultra per member, Codex Micro, ChatGPT Pro ×1yr. CONTEXT.md's "$3,000" is low.

### Forum, answered in the last ~36 hours
- **"Demo Video Requirement – Conflicting FAQ Information"** (Samuel Philip, Sep 2 → Shawni, Devpost manager, ~14h ago). The Resources FAQ contradicted itself; **it has been corrected**. Confirmed: *"the demo video is required… Your submission needs all three: a working live URL, a public code repository with an open source license file, and the demo video."* And: *"Judges are not required to test the Project and may choose to judge based solely on the text description, images, and video provided in the Submission."* → the video + description must stand alone.
- **"Enforced code snippet requested?"** (Luis J Camargo → Shawni, Sep 2). The `registerTool({name:"search_products"…})` snippet in the welcome email is **not required verbatim**: *"You do not need a tool named search_products… Your React pattern is fine. useMcpTool from react-webmcp registers tools through the same underlying API."* What is required is *"All necessary source code, assets, and instructions required for the project to be functional"* plus a real working implementation.
- **"ChatGPT Chrome plugin latest version issue"** (Oscar Sanchez Iglesias, closed Sep 2). Codex Chrome plugin 1.2.27268.51612 on Chrome 152 failed with *"I can see select_number is registered, but it isn't exposed as callable in this session."* Organizer: test a deployed URL, not localhost; use ChatGPT's in-app browser. Participant's own resolution, useful for our README: **WebMCP is not supported in ChatGPT Desktop on Enterprise or Edu plans**; on a consumer plan the in-app browser settings show an **"Enable site Tools" toggle**.
- Still unanswered: whether a browser extension that *consumes* tools qualifies (we expose, unaffected); repo scope for pre-existing platforms.
- No new organizer guidance on tool design, security budgets or the theme since Aug 31. The Chrome evals/build-tools/secure-tools guides Sarah Drasner flagged remain the latest judge-side signal.
